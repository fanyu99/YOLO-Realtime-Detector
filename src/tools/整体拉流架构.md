










# 更改：暂停/停止拉流时的机制-暂停/停止的语义分割
1. 在中断上下文中添加条件变量pause用于判断是否为暂停；然后在读取循环中进行判断是否为暂停，暂停时使用条件变量阻塞线程（等待直到恢复或者更高级别的**停止**）
原本的中断上下文进行语义分割：pause表示是否暂停、stop表示是否停止；中断回调函数两个均返回1（中断）
2. 暂停时通过使用条件变量在`readAndDecodeLoop()`中阻塞线程，从而实现暂停拉流的功能。暂停时，解码线程会进入等待状态(条件变量m_pauseCV进行阻塞)，直到收到恢复信号。
而停止时，通过设置stop,直接停止解码线程的循环，退出线程。
其中的`receiveFrames()`函数只检查是否停止，暂停时会将剩余的所有帧返回，符合真实情景，不需要进行修正
3. 原先的m_running标志位用来表示是否正在解码，**现在进行更改为：是否正在工作，即只要不停止(stop)，就为true** ；经过统一的`finish()`函数进行统一的复位(false)
4. 暂停/恢复拉流时只改变中断上下文中的pause标志位；恢复拉流时，进行唤醒线程`notify_all()`  
5. 在`startDecoding()`函数中，复位pause/stop等标志位
6. controller中，采用直接调用`pause`/`resume`
注意事项：等待方使用锁进行等待时，通知方需要使用同一把锁进行修改等待标志位，防止出现 *通知丢失* 的情况。
