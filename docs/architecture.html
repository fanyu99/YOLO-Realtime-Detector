1. 当前系统总览

Manager 管理 Job 状态并投递 Task，Worker 消费 Task 队列。Session 在线程内创建和重建，统一选择帧源工厂和推理 Flow。为控制总览复杂度，帧源实现、CPU/GPU Flow 实现和结果服务分别合并展示。

当前不是 Job 队列模型。Session 也不是每个 Job 结束时立即销毁。fallback 时由 Worker 重建 CPU 会话，再经 Manager、App 将状态和提示回传给 QML。

2. 帧与推理路径

  • CPU：BGR 帧 → CPU 预处理 → ONNX Runtime CPU → CPU 后处理/NMS。
  • GPU 视频：CUDA/NV12 帧 → CUDA 预处理 → ONNX Runtime CUDA → CPU 后处理/NMS。
  • GPU 图片：CPU BGR 帧 → Session 上传显存 → BGR CUDA kernel → GPU 推理 → CPU 后处理/NMS。
  • 显示和保存：CPU 图像 → DetectionRenderer → QImage / 文件。GPU Overlay 尚未接入。

3. 性能监控数据流

PerformanceApp 创建并持有真实监测器或空实现，各阶段只借用接口指针。图中的箭头表示记录和快照的传递，不表示所有权转移。

Basic 采集端到端统计；Detailed 增加读帧、预处理、推理、后处理、绘制与保存；Full 再增加上传阶段。监测器通过锁保护聚合数据，快照在显示边界由纳秒转换为毫秒。

这些数据是主机侧埋点作用域耗时。当前没有完整的内存采样和 CUDA Event 计时，也没有持久化监控开关；启动配置来自 main.cpp。
