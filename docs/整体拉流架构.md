# 整体拉流架构

## 一、当前总体架构

### RtspDecodeWorker

- 负责底层 FFmpeg 的 RTSP 拉流：通过 `FrameUpdated()` 信号，以 `LatestFrameStore` 结构体（内部使用 `QImage` 缓存帧）作为参数通知 Controller 进行缓存。
- 内部使用 `RtspStreamStatus` 进行状态统计：统计解码帧数、显示帧数等状态信息。

#### 开始解码：`startDecoding()`

- 每次 `startDecoding()` 作为一次 Worker 的会话（Session）。
- 防并发设计：使用原子变量的交换进行校验，判断是否正在进行工作；若正在进行工作，则返回并汇报错误。
- 依次进行成员数据复位、参数校验，然后打开输入 `openInput()`、初始化解码器 `initDecoder()`、读取 packet 并解码取帧循环 `readAndDecodeLoop()`。
- 最后校验是否运行成功（`clean` 作为是否成功解码并读取所有帧的标志位），并通过 `finish` lambda 函数进行统一的资源清理与会话结束上报（`finished()` 信号）。

**`finished(clean, error)` 信号语义**

- `clean == false`：没有正常读取完所有帧，即出现错误导致结束，`error` 为最近一次的错误。
- `clean == true`：会话正常结束，`error` 为空。

#### 打开输入：`openInput()`

流程：

1. 创建 `AVFormatContext`，设置中断上下文、中断回调及各项参数（包括 TCP 等 option）。
2. 打开 RTSP 流，并将流的信息查找入上下文 `AVFormatContext` 中。

#### 初始化解码器：`initDecoder()`

流程：

1. 查找视频流索引。
2. 根据对应视频流中的解码器 ID 查找解码器。
3. 创建解码器上下文，并将视频流中的各项参数传入上下文。
4. 开启解码器，为 packet 与 frame 分配内存，并记录流信息（包括名义 FPS 等）。

#### 读取、解码循环：`readAndDecodeLoop()`

流程：

- `while (!isStopRequested())` 循环：请求停止时直接退出循环。
- 循环内部检查是否暂停；暂停时使用条件变量阻塞并挂起线程，随后读取压缩包并交给解码器解码，最后使用 `receiveFrames()` 循环接收解码器解码该 packet 后的所有帧。
- 正常 EOF 退出时，发送空包 flush 解码器中缓存的帧，并调用 `receiveFrames()` 接收。

### RtspStreamController

负责与 QML 对接，管理底层 Worker 的各种操作，实现重连机制，维护状态信息并上报给 QML。

#### 开始拉流：`start()`（由 `launchWorker()` 启动 Worker）

- `launchWorker()` 内部进行懒加载：创建 Worker 与 Worker 线程，应用配置，并启动 Worker 解码。
- `ensureWorkerCreated()` 函数负责**懒加载**：创建 Worker 和线程，并连接信号槽（状态转发、错误转发、会话结束的重连机制 `onWorkerFinished()`、帧转发、流信息更新、统计信息转发）。

#### 停止拉流：`stop()`

调用 Worker 的 `requestStop()`；如果 Worker 本来就已停止，则直接设置状态。

#### 暂停 / 恢复：`pause()`、`resume()`

调用 Worker 的 `pauseDecoding()`；Worker 的暂停机制详见下文「更改 1」。

#### 重连机制

**触发流程**：Worker 的 `finished(clean, error)` 信号发出后，Controller 接收并调用 `onWorkerFinished()`，检查是否出错且错误可重连；若可重连，则调用 `scheduleRetry()` 安排重连。

重连机制由 Controller 实现：

1. 内部维护重连进度字段 `RetryProgress`，记录重连进度。
2. 使用 `scheduleRetry()` 规划**带退避**的重连，防止短时间内多次重连导致崩溃；退避时间随重连次数增加。
3. 重连定时器结束后，再次调用 `launchWorker()` 重启 Worker。
4. 重连超过最大次数后，调用 `giveUp()` 放弃，并统一汇报错误、设置状态。

重连信号通知机制：

- `ReconnectAttempt()`：汇报第 n 次重连。
- `ReconnectFailed()`：汇报彻底重连失败。
- `Reconnecting()`：表示进入重连等待。

### 状态机

使用统一的 `RtspOverallStatus` 表示状态。

#### Worker

Worker 不存储当前状态，而是通过信号向 Controller 上报状态。Worker 中存在至少以下状态转换：

```text
Idle(空闲)
  -> Opening(正在打开，startDecoding() 中 openInput() 之前变更)
  -> Opened(打开完成，openInput() 完成时变更)
  -> Playing(正在播放，emitDecodedFrame() 于发送第一帧时变更)
  -> Stopped(停止，在上层 Controller 的 onWorkerFinished() 中变更)
```

另外，如果出现错误，使用统一的 `reportError()` 函数上报错误；在上层 Controller 重连失败时，将状态设置为 `Error`。

#### Controller

由 Worker 上报状态，Controller 缓存状态并由 QML 获取。除 Worker 状态外，至少存在以下状态转换：

```text
Idle
  -> Opening
  -> Opened
  -> Playing
  -> Reconnecting(出现错误且设置了自动重连 autoReconnect 时，进行退避重连)
  -> Stopped(重连失败，在 onWorkerFinished() 中变更)
  -> Error(giveUp() 函数设置)
```

## 二、更改 1：暂停 / 停止拉流时的机制 —— 暂停 / 停止的语义分割

1. 在中断上下文中添加条件变量 `pause` 用于判断是否为暂停；然后在读取循环中进行判断，暂停时使用条件变量阻塞线程（等待恢复或更高级别的**停止**）。
   - 原本的中断上下文进行语义分割：`pause` 表示是否暂停，`stop` 表示是否停止；中断回调函数对两者均返回 1（中断）。
2. 暂停时，通过条件变量在 `readAndDecodeLoop()` 中阻塞线程，从而实现暂停拉流。暂停时，解码线程进入等待状态（由条件变量 `m_pauseCV` 阻塞），直到收到恢复信号；而停止时，通过设置 `stop` 直接停止解码线程的循环并退出线程。
   - 其中 `receiveFrames()` 函数只检查是否停止；暂停时会将剩余所有帧返回，符合真实情景，无需修正。
3. 原先的 `m_running` 标志位表示是否正在解码，**现更改为：是否正在工作，即只要未停止（`stop`）就为 `true`**；由统一的 `finish()` 函数统一复位（`false`）。
4. 暂停 / 恢复拉流时只改变中断上下文中的 `pause` 标志位；恢复拉流时，调用 `notify_all()` 唤醒线程。
5. 在 `startDecoding()` 函数中，复位 `pause` / `stop` 等标志位。
6. Controller 中采用直接调用 `pause()` / `resume()` 的方式。

> **注意**：等待方使用锁进行等待时，通知方需要使用同一把锁修改等待标志位，防止出现*通知丢失*的情况。

## 三、更改 2：拉流统计信息以及上报机制

1. 添加 `RtspStreamStatus` 结构体，其中新增以下统计信息供 QML 显示：

    ```cpp
    quint64    receivedPacketCount { 0 };  // 收到的 packet 数（包含非视频包）
    quint64    videoPacketCount { 0 };     // 视频 packet 数
    quint64    decodedFrameCount { 0 };    // 解码帧数
    quint64    displayedFrameCount { 0 };  // 显示帧数（成功转换并发出 frameDecoded）
    quint64    droppedFrameCount { 0 };    // 覆盖或丢弃帧数（解码后未能显示）
    double     decodeFps { 0.0 };          // 解码 FPS（实测）
    double     displayFps { 0.0 };         // 显示 FPS（实测）
    qint64     lastPts { -1 };             // 最近一次 PTS（-1 = AV_NOPTS_VALUE）
    quint64    lastReadTime { 0 };         // 最近一次成功读取视频包的时间（us）
    quint64    decodeErrorCount { 0 };     // 解码错误数
    int        reconnectCount { 0 };       // 重连次数（由 Controller 填写）
    RtspStatus currentStatus { RtspStatus::Idle };  // 当前状态（由 Controller 填写）
    ```

2. 添加 `streamStatusChanged()` 信号，并在 `reportStreamStatus()` 函数中按固定间隔（1 s）汇总并上报统计信息。

# QML侧对接的API

QML 侧只与 `RtspStreamController`（控制面）和 `RtspImageProvider`（画面通道）对接，不直接接触 `RtspDecodeWorker`。下文清单以当前头文件为准（`Qt6`，`RtspStreamController.h` / `RtspTypes.h` / `RtspImageProvider.h`）。

## 一、对接边界

| 通道 | 承担者 | QML 侧用途 |
| --- | --- | --- |
| 控制面 | `RtspStreamController` | 开始/停止/暂停/恢复、URL 与重连策略配置、状态与错误、流信息、统计信息 |
| 画面面 | `RtspImageProvider` + `image://rtsp/...` | `Image.source` 显示最新帧 |
| 帧元信息 | `Controller.lastestFrameStore` / `FrameUpdated` | 帧序号、PTS、读取/解码时间 |

## 二、接入前提

1. **Controller 注入**：`RtspStreamController` 当前没有 `QML_ELEMENT`，需要在 C++ 侧注册或注入（二选一）：
   - 类型注册：`qmlRegisterType<RtspStreamController>("Rtsp", 1, 0, "RtspStreamController")`；
   - 上下文注入：`engine.rootContext()->setContextProperty("rtspController", controller)`。
2. **帧通道注册**：`engine.addImageProvider("rtsp", new RtspImageProvider)`，随后 QML 使用 `image://rtsp/live`。提供者 id `"rtsp"` 与 URL 前缀必须一致；`RtspImageProvider` 没有类似 `providerId()` 的辅助函数，需要自行约定。
3. **帧推送**：`RtspStreamController::FrameUpdated` 与 `RtspImageProvider::updateFrame` 是两条独立路径，需要显式连接（提供者不是 `QObject`，用 lambda + 上下文对象连接）：

   ```cpp
   QObject::connect(controller, &RtspStreamController::FrameUpdated, controller,
                    [provider](const LastestFrameStore& frame) {
                        provider->updateFrame(frame); // 线程安全，内部加锁
                    });
   ```

4. **类型注册**：`RtspStatus`、`RtspOverallError`、`RtspDataContext`、`LastestFrameStore`、`RtspStreamStatus` 均为 `Q_GADGET`，且未标注 `QML_ELEMENT`。要让 QML 直接读取其成员/枚举（如 `streamStatus.decodeFps`、`RtspOverallStatus.Playing`），需要在 C++ 侧额外注册（`QML_VALUE_TYPE`，Qt 6.5+；或 `qmlRegisterUncreatableMetaObject` 暴露枚举）。未注册时，枚举请用数值比较不推荐，建议一并注册。
5. **`RtspConfig` 不能从 QML 构造**：其成员含 `std::optional<QString>`，QML 侧不要给 `inputConfig` 赋值；需要改 URL / 重连策略时分别调用 `setUrl()`、`setAutoReconnect()`、`setMaxReconnect()`。

## 三、属性清单（QML 可读，部分可写）

| 属性名 | 类型 | 读写 | 通知信号 | 说明 |
| --- | --- | --- | --- | --- |
| `rtspUrl` | `QUrl` | 读写 | `RtspUrlChanged` | 写入后触发 **150 ms 防抖重启**，见「限制」第 2 条 |
| `inputConfig` | `RtspConfig` | 读写 | `InputConfigChanged` | 整体配置；QML 实际不可构造，写入留给 C++ |
| `currentStatus` | `RtspStatus`（枚举） | 只读 | `StatusChanged` | 状态机当前状态，推荐 UI 唯一依据 |
| `currentError` | `RtspOverallError` | 只读 | `ErrorOccurred` | 最近一次错误；**清空不会通知 QML** |
| `streamStatus` | `RtspStreamStatus` | 只读 | `StreamStatusChanged` | 统计快照，约 1 s 刷新一次 |
| `dataContext` | `RtspDataContext` | 只读 | `DataContextChanged` | 打开流成功后才有有效值；停止后不清空 |
| `lastestFrameStore` | `LastestFrameStore` | 只读 | `FrameUpdated` | 最新帧元信息（含 `QImage`，不建议直接绑定显示） |
| `autoReconnect` | `bool` | 读写 | `AutoReconnectChanged` | 只影响重连策略，不重启当前流 |
| `maxReconnect` | `int` | 读写 | `AutoReconnectChanged` | 与上一项共用通知信号，默认 5 |
| `retryCount` | `int` | 只读 | `RetryCountChanged` | 已重连次数；成功进入 `Playing` 时清零 |

> 属性通知信号多数不符合 `<属性名>Changed` 约定，QML 自动生成的处理器名以信号名为准：`onStatusChanged`、`onErrorOccurred`、`onRetryCountChanged`、`onStreamStatusChanged`、`onDataContextChanged`、`onFrameUpdated`、`onRtspUrlChanged`、`onInputConfigChanged`、`onAutoReconnectChanged`。

## 四、可调用方法（`Q_INVOKABLE`）

| 方法 | 返回 | 前置条件 / 副作用 |
| --- | --- | --- |
| `start()` | `bool` | 配置非法：发 `ErrorOccurred(InvalidConfig)`、返回 `false`，**状态不变**；已在拉流或等待重连：直接返回 `true`（幂等）；正常：置 `Opening` 并异步启动，返回时尚未连接完成 |
| `stop()` | `void` | 取消重连定时器并请求 Worker 停止；最终经 `Finished` → `Stopped`；等待重连中调用会直接取消重连并置 `Stopped` |
| `pause()` | `void` | 仅 `Playing` 时生效，成功后状态变 `Paused`；其余状态静默忽略 |
| `restart()` | `bool` | **语义是「恢复」，不是重启**；仅 `Paused` 时生效并返回 `true`；否则发 `ErrorOccurred(Other)` 并返回 `false` |
| `setUrl(QUrl url)` | `void` | 只写 URL，不校验合法性；合法性在 Worker 打开时校验并上报 `InvalidUrl` |
| `setAutoReconnect(bool)` | `void` | 关闭时若正在等待重连，会取消重连并把状态置 `Error`（**不发 `ReconnectFailed`**） |
| `setMaxReconnect(int)` | `void` | 负值按 0 处理；只影响后续重连上限 |

> 以下成员**没有** `Q_INVOKABLE`，QML 不可调用：`setInputConfig()`、`isStreaming()`、`releaseResources()`、`start()` 以外的内部管理。`isStreaming` 可用 `currentStatus === Playing`（或 `Opening/Opened/Playing/Paused/Reconnecting`）自行判断。

## 五、信号清单

| 信号 | 参数 | 触发时机 |
| --- | --- | --- |
| `StatusChanged` | `RtspStatus status` | 状态真正变化时（内部已去重，同值不重复发） |
| `StreamStatusChanged` | `RtspStreamStatus status` | 每次状态变化、以及 Worker 每 1 s 汇总一次统计 |
| `FrameUpdated` | `LastestFrameStore newFrame` | 每解码出一帧（实时流约每秒 25~30 次） |
| `DataContextChanged` | `RtspDataContext newInfo` | 打开流并读到有效流信息后 |
| `ErrorOccurred` | `RtspOverallError error` | 每次错误；**重连过程中的中间错误也会发** |
| `Reconnecting` | 无 | 进入重连等待 |
| `ReconnectAttempt` | `int attempt, int maxAttempts` | 安排第 `attempt` 次重连时 |
| `ReconnectFailed` | `int attempts, RtspOverallError lastError` | 重连彻底失败（终态）；随后还会再发一次 `ErrorOccurred` |
| `RetryCountChanged` | 无 | `retryCount` 变化（含进入 `Playing` 时清零） |
| `RtspUrlChanged` / `InputConfigChanged` / `AutoReconnectChanged` | 无 | 对应的属性通知 |

信号顺序约定：出错时先 `ErrorOccurred`，再视情况 `Reconnecting` → `ReconnectAttempt`；放弃时 `ReconnectFailed` → `ErrorOccurred`。

## 六、数据结构字段

**`RtspStreamStatus`**（统计快照，`Q_PROPERTY MEMBER` 可读）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `receivedPacketCount` | `quint64` | 收到的 packet 总数（含非视频包） |
| `videoPacketCount` | `quint64` | 视频 packet 数 |
| `decodedFrameCount` | `quint64` | 解码帧数 |
| `displayedFrameCount` | `quint64` | 成功转换并发出的帧数 |
| `droppedFrameCount` | `quint64` | 转换失败被丢弃的帧数 |
| `decodeFps` / `displayFps` | `double` | 实测解码 / 显示帧率（按 1 s 窗口计算） |
| `lastPts` | `qint64` | 最近一次 PTS，`-1` 表示无 PTS |
| `lastReadTime` | `quint64` | 最近一次成功读取视频包的时间（µs） |
| `decodeErrorCount` | `quint64` | 解码错误数 |
| `reconnectCount` | `int` | 由 Controller 填写，等于 `retryCount` |
| `currentStatus` | `RtspStatus` | 由 Controller 填写 |

注意：Worker 每次新会话会把统计清零，Controller 不会在停止后重置，因此 `Stopped` 后读到的是上一会话的末值。

**`LastestFrameStore`**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `lastestFrame` | `QImage` | 最新帧本体（名字拼写即 `Lastest`） |
| `frameIndex` | `quint64` | 帧序号，**每次会话从 0 开始** |
| `pts` | `qint64` | PTS，`-1` 表示无 PTS |
| `ptsSeconds` | `double` | PTS 秒数，`-1` 表示无效 |
| `readTime` / `decodedTime` | `quint64` | 读包 / 解码完成时间（µs） |

**`RtspDataContext`**：`containerFormat`、`codecName`、`formatName`、`pixelFormat`、`colorSpace`、`color_range`、`timeBase`、`width`、`height`、`fps`（名义帧率）、`videoStreamIndex`。

**`RtspOverallError`**：只有 `getErrorMessage()`、`getErrorCode()` 两个 `Q_INVOKABLE` 可读（成员本身没有 `Q_PROPERTY`）。

**`RtspConfig`**：`url`、`username`、`password`（`std::optional<QString>`）、`maxReconnect`（默认 5）、`connectTimeoutMs`（默认 5000）、`readTimeoutMs`（默认 5000）、`autoReconnect`（默认 `false`）。仅作 QML 展示用。

## 七、枚举

**`RtspOverallStatus::Status`**

| 值 | 含义 |
| --- | --- |
| `Idle` | 初始 / 未拉流 |
| `Opening` | Controller 已启动 Worker，正在打开 RTSP |
| `Opened` | 输入已打开、流信息已读取，等待第一帧 |
| `Playing` | 首帧已解码 / 恢复成功 |
| `Paused` | 已暂停（解码线程仍存活，仅阻塞读取循环） |
| `Reconnecting` | 出错且 `autoReconnect` 开启、错误可重试，退避等待中 |
| `Stopping` | 已定义，**当前实现不会上报** |
| `Stopped` | 主动停止或正常 EOF |
| `Error` | 重连超限（`giveUp()`）后的终态 |

**`RtspOverallError::ErrorCode`**

| 值 | 来源与说明 | 可重连 |
| --- | --- | --- |
| `NoError` | 无错误 | — |
| `InvalidUrl` | Worker 打开前校验 URL / URL 为空 | 否 |
| `ConnectionFailed` | 打开 RTSP 流或读取流信息失败（含认证失败，FFmpeg 仅给出文本） | 是 |
| `ReconnectFailed` | Controller `giveUp()` 填写 | 否（终态） |
| `AuthenticationFailed` | 已定义，当前未被使用 | 否 |
| `StreamNotFound` | 找不到视频流 / 找不到解码器 | 否 |
| `StreamFailed` | 已定义，当前未被使用（打开失败归入 `ConnectionFailed`） | 是 |
| `ReadTimeout` | 连接、流信息、读包任一阶段超时 | 是 |
| `InvalidConfig` | `start()` 时配置非法 | 否 |
| `AlreadyRunning` | 同一 Worker 上并发 `startDecoding()` | 否 |
| `Other` | 解码器创建 / 送包 / 收帧 / 像素转换等错误 | 是 |

## 八、状态 → 界面可用性建议

| 状态 | 界面提示 | 建议可操作 |
| --- | --- | --- |
| `Idle` / `Stopped` | 未拉流 | `start()` |
| `Opening` / `Opened` | 连接中 | `stop()` |
| `Playing` | 播放中，显示 `streamStatus.displayFps` | `pause()`、`stop()` |
| `Paused` | 已暂停 | `restart()`（恢复）、`stop()` |
| `Reconnecting` | 第 `retryCount` / `maxReconnect` 次重连 | `stop()`（取消重连） |
| `Error` | 显示 `currentError.getErrorMessage()` | `start()`（重新尝试）、调参后重试 |

`Stopping` 分支可以保留但不需处理，当前实现不会出现。

## 九、QML 示例

```qml
import QtQuick
import QtQuick.Controls

Column {
    spacing: 8

    // 画面：走 image provider；靠帧序号绕过 QML 图片缓存
    Image {
        id: preview
        width: 640
        height: 360
        fillMode: Image.PreserveAspectFit
        source: {
            const s = rtspController.currentStatus
            return (s === RtspOverallStatus.Playing || s === RtspOverallStatus.Paused)
                    ? "image://rtsp/live?" + rtspController.lastestFrameStore.frameIndex
                    : ""
        }
    }

    Text {
        text: {
            switch (rtspController.currentStatus) {
            case RtspOverallStatus.Opening:
            case RtspOverallStatus.Opened:      return "连接中…"
            case RtspOverallStatus.Playing:     return "播放中 " + rtspController.streamStatus.displayFps.toFixed(1) + " fps"
            case RtspOverallStatus.Paused:      return "已暂停"
            case RtspOverallStatus.Reconnecting:
                return "重连中 " + rtspController.retryCount + "/" + rtspController.maxReconnect
            case RtspOverallStatus.Error:       return "错误：" + rtspController.currentError.getErrorMessage()
            default:                            return "未拉流"
            }
        }
    }

    Row {
        spacing: 8
        Button {
            text: "开始"
            enabled: rtspController.currentStatus === RtspOverallStatus.Idle
                     || rtspController.currentStatus === RtspOverallStatus.Stopped
                     || rtspController.currentStatus === RtspOverallStatus.Error
            onClicked: rtspController.start()
        }
        Button {
            text: "暂停"
            enabled: rtspController.currentStatus === RtspOverallStatus.Playing
            onClicked: rtspController.pause()
        }
        Button {
            text: "恢复"
            enabled: rtspController.currentStatus === RtspOverallStatus.Paused
            onClicked: rtspController.restart()   // 注意：restart() 是恢复
        }
        Button {
            text: "停止"
            enabled: rtspController.currentStatus !== RtspOverallStatus.Idle
                     && rtspController.currentStatus !== RtspOverallStatus.Stopped
                     && rtspController.currentStatus !== RtspOverallStatus.Error
            onClicked: rtspController.stop()
        }
    }

    Connections {
        target: rtspController
        function onErrorOccurred(error) { console.warn("RTSP:", error.getErrorMessage()) }
        function onReconnectFailed(attempts, lastError) { console.warn("重连失败", attempts) }
    }
}
```

## 十、已知限制与注意点

1. **`restart()` 名字有误导**：它只负责恢复暂停，不会重新建立连接。需要重新连接请 `stop()` + `start()`，或写入新的 `rtspUrl`。
2. **`setUrl()` / `inputConfig` 会触发防抖重启**：写入后 150 ms 应用。若当前未拉流且配置有效，**会直接开始拉流**；正在拉流会先停止再按新配置重启；正在等待重连会立即用新配置重启。
3. **`start()` 失败不发状态变更**：配置非法时状态保持原值，UI 必须以 `ErrorOccurred` 或返回值为准，不能只看 `currentStatus`。
4. **`ErrorOccurred` 不等于终态**：`autoReconnect` 开启时，中间错误也会触发该信号，随后进入 `Reconnecting`。UI 只在 `currentStatus === Error` 或收到 `ReconnectFailed` 时展示致命错误。
5. **关闭 `autoReconnect` 的边界**：等待重连期间关闭会直接置 `Error`，但不会发 `ReconnectFailed`，UI 不要只依赖该信号。
6. **`currentError` 不会被通知清空**：`start()` 会重置内部错误对象，但不发信号，绑定到 `currentError` 的界面不会自动刷新。
7. **暂停不结束会话**：`pause()` 只阻塞读取循环，不产生 `Finished`、不释放资源；`stop()` 才会结束会话。
8. **`Stopping` 不会出现**：Worker 不上报该状态，可保留分支但不必处理。
9. **帧序号每次会话从 0 重新开始**：用 `frameIndex` 做缓存绕过时，重连/重新开始可能命中上一次会话的缓存图片，建议同时拼上会话标识或时间戳，并在 `Stopped` / `Error` 时把 `source` 置空。
10. **提供者不会自动清帧**：`stop()` 不会清空 `RtspImageProvider`，需要在 C++ 侧连接 `StatusChanged` 到 `Stopped` / `Error` 时调用 `clear()`。
11. **`FrameUpdated` 是高频信号**：不要在其处理器里做重活，画面显示统一走 `image://rtsp`，该信号只用于元信息。
