# 整体拉流架构

## 一、当前总体架构

### RtspDecodeWorker

- 负责底层 FFmpeg 的 RTSP 拉流：通过 `FrameUpdated()` 信号，以 `LatestFrameStore` 结构体（内部使用 `QImage` 缓存帧）作为参数通知 Controller 进行缓存。
- 内部使用 `RtspStreamStatus` 进行状态统计：统计解码帧数、显示帧数等状态信息。

#### 开始解码：`startDecoding()`

- 每次 `startDecoding()` 作为一次 Worker 的会话（Session）。
- 防并发设计：使用原子变量的交换进行校验，判断是否正在进行工作；若正在进行工作，则返回并汇报错误。
- 依次进行成员数据复位、参数校验，然后打开输入 `openInput()`、初始化解码器 `initDecoder()`、读取 packet 并解码取帧循环 `readAndDecodeLoop()`。
- 最后校验是否运行成功（`clean` 作为是否成功解码并读取所有帧的标志位），并通过 `finish` lambda 函数进行统一的资源清理与会话结束上报（`finished()` 信号）。

**`finished(clean, error)` 信号语义**

- `clean == false`：没有正常读取完所有帧，即出现错误导致结束，`error` 为最近一次的错误。
- `clean == true`：会话正常结束，`error` 为空。

#### 打开输入：`openInput()`

流程：

1. 创建 `AVFormatContext`，设置中断上下文、中断回调及各项参数（包括 TCP 等 option）。
2. 打开 RTSP 流，并将流的信息查找入上下文 `AVFormatContext` 中。

#### 初始化解码器：`initDecoder()`

流程：

1. 查找视频流索引。
2. 根据对应视频流中的解码器 ID 查找解码器。
3. 创建解码器上下文，并将视频流中的各项参数传入上下文。
4. 开启解码器，为 packet 与 frame 分配内存，并记录流信息（包括名义 FPS 等）。

#### 读取、解码循环：`readAndDecodeLoop()`

流程：

- `while (!isStopRequested())` 循环：请求停止时直接退出循环。
- 循环内部检查是否暂停；暂停时使用条件变量阻塞并挂起线程，随后读取压缩包并交给解码器解码，最后使用 `receiveFrames()` 循环接收解码器解码该 packet 后的所有帧。
- 正常 EOF 退出时，发送空包 flush 解码器中缓存的帧，并调用 `receiveFrames()` 接收。

### RtspStreamController

负责与 QML 对接，管理底层 Worker 的各种操作，实现重连机制，维护状态信息并上报给 QML。

#### 开始拉流：`start()`（由 `launchWorker()` 启动 Worker）

- `launchWorker()` 内部进行懒加载：创建 Worker 与 Worker 线程，应用配置，并启动 Worker 解码。
- `ensureWorkerCreated()` 函数负责**懒加载**：创建 Worker 和线程，并连接信号槽（状态转发、错误转发、会话结束的重连机制 `onWorkerFinished()`、帧转发、流信息更新、统计信息转发）。

#### 停止拉流：`stop()`

调用 Worker 的 `requestStop()`；如果 Worker 本来就已停止，则直接设置状态。

#### 暂停 / 恢复：`pause()`、`resume()`

调用 Worker 的 `pauseDecoding()`；Worker 的暂停机制详见下文「更改 1」。

#### 重连机制

**触发流程**：Worker 的 `finished(clean, error)` 信号发出后，Controller 接收并调用 `onWorkerFinished()`，检查是否出错且错误可重连；若可重连，则调用 `scheduleRetry()` 安排重连。

重连机制由 Controller 实现：

1. 内部维护重连进度字段 `RetryProgress`，记录重连进度。
2. 使用 `scheduleRetry()` 规划**带退避**的重连，防止短时间内多次重连导致崩溃；退避时间随重连次数增加。
3. 重连定时器结束后，再次调用 `launchWorker()` 重启 Worker。
4. 重连超过最大次数后，调用 `giveUp()` 放弃，并统一汇报错误、设置状态。

重连信号通知机制：

- `ReconnectAttempt()`：汇报第 n 次重连。
- `ReconnectFailed()`：汇报彻底重连失败。
- `Reconnecting()`：表示进入重连等待。

### 状态机

使用统一的 `RtspOverallStatus` 表示状态。

#### Worker

Worker 不存储当前状态，而是通过信号向 Controller 上报状态。Worker 中存在至少以下状态转换：

```text
Idle(空闲)
  -> Opening(正在打开，startDecoding() 中 openInput() 之前变更)
  -> Opened(打开完成，openInput() 完成时变更)
  -> Playing(正在播放，emitDecodedFrame() 于发送第一帧时变更)
  -> Stopped(停止，在上层 Controller 的 onWorkerFinished() 中变更)
```

另外，如果出现错误，使用统一的 `reportError()` 函数上报错误；在上层 Controller 重连失败时，将状态设置为 `Error`。

#### Controller

由 Worker 上报状态，Controller 缓存状态并由 QML 获取。除 Worker 状态外，至少存在以下状态转换：

```text
Idle
  -> Opening
  -> Opened
  -> Playing
  -> Reconnecting(出现错误且设置了自动重连 autoReconnect 时，进行退避重连)
  -> Stopped(重连失败，在 onWorkerFinished() 中变更)
  -> Error(giveUp() 函数设置)
```

## 二、更改 1：暂停 / 停止拉流时的机制 —— 暂停 / 停止的语义分割

1. 在中断上下文中添加条件变量 `pause` 用于判断是否为暂停；然后在读取循环中进行判断，暂停时使用条件变量阻塞线程（等待恢复或更高级别的**停止**）。
   - 原本的中断上下文进行语义分割：`pause` 表示是否暂停，`stop` 表示是否停止；中断回调函数对两者均返回 1（中断）。
2. 暂停时，通过条件变量在 `readAndDecodeLoop()` 中阻塞线程，从而实现暂停拉流。暂停时，解码线程进入等待状态（由条件变量 `m_pauseCV` 阻塞），直到收到恢复信号；而停止时，通过设置 `stop` 直接停止解码线程的循环并退出线程。
   - 其中 `receiveFrames()` 函数只检查是否停止；暂停时会将剩余所有帧返回，符合真实情景，无需修正。
3. 原先的 `m_running` 标志位表示是否正在解码，**现更改为：是否正在工作，即只要未停止（`stop`）就为 `true`**；由统一的 `finish()` 函数统一复位（`false`）。
4. 暂停 / 恢复拉流时只改变中断上下文中的 `pause` 标志位；恢复拉流时，调用 `notify_all()` 唤醒线程。
5. 在 `startDecoding()` 函数中，复位 `pause` / `stop` 等标志位。
6. Controller 中采用直接调用 `pause()` / `resume()` 的方式。

> **注意**：等待方使用锁进行等待时，通知方需要使用同一把锁修改等待标志位，防止出现*通知丢失*的情况。

## 三、更改 2：拉流统计信息以及上报机制

1. 添加 `RtspStreamStatus` 结构体，其中新增以下统计信息供 QML 显示：

    ```cpp
    quint64    receivedPacketCount { 0 };  // 收到的 packet 数（包含非视频包）
    quint64    videoPacketCount { 0 };     // 视频 packet 数
    quint64    decodedFrameCount { 0 };    // 解码帧数
    quint64    displayedFrameCount { 0 };  // 显示帧数（成功转换并发出 frameDecoded）
    quint64    droppedFrameCount { 0 };    // 覆盖或丢弃帧数（解码后未能显示）
    double     decodeFps { 0.0 };          // 解码 FPS（实测）
    double     displayFps { 0.0 };         // 显示 FPS（实测）
    qint64     lastPts { -1 };             // 最近一次 PTS（-1 = AV_NOPTS_VALUE）
    quint64    lastReadTime { 0 };         // 最近一次成功读取视频包的时间（us）
    quint64    decodeErrorCount { 0 };     // 解码错误数
    int        reconnectCount { 0 };       // 重连次数（由 Controller 填写）
    RtspStatus currentStatus { RtspStatus::Idle };  // 当前状态（由 Controller 填写）
    ```

2. 添加 `streamStatusChanged()` 信号，并在 `reportStreamStatus()` 函数中按固定间隔（1 s）汇总并上报统计信息。
